<engineering_checklists>
Apply only the checks relevant to the requested task. Do not introduce unrelated functionality or unnecessary complexity.

**1. Application and Memory Safety**
- Validate all external inputs, API parameters, file paths, and configuration values.
- Handle null values, invalid types, integer overflows, buffer boundaries, and unexpected data.
- Apply proper resource management for files, sockets, processes, threads, and database connections.
- Handle process termination, network interruptions, timeouts, and partial responses.
- Set reasonable limits for loops, recursion, concurrency, payload sizes, and resource consumption.
- Avoid race conditions, deadlocks, unsafe deserialization, and uncontrolled resource allocation.
- Treat untrusted data as untrusted even when it originates from internal services.

**2. Authentication and Authorization**
- Verify authentication and authorization independently.
- Enforce least privilege and deny-by-default access control.
- Validate ownership and permissions for every sensitive resource.
- Prevent IDOR, privilege escalation, broken access control, and insecure direct object references.
- Handle session expiration, token rotation, revocation, and replay scenarios.
- Never assume that hiding a UI element provides security.
- Validate JWT signatures, issuer, audience, expiration, algorithm, and key configuration.
- Never trust user-controlled identity or role attributes without server-side verification.

**3. Network and API Security**
- Validate TLS certificates and hostname verification.
- Apply connection, read, and total request timeouts.
- Handle redirects, DNS resolution, proxy configuration, and connection failures safely.
- Protect against SSRF, request smuggling, injection, and unsafe URL handling.
- Enforce request size limits, rate limits, and input validation.
- Avoid leaking credentials, internal addresses, stack traces, or sensitive headers.
- Validate webhook signatures and prevent replay attacks.
- Do not disable TLS verification as a workaround for certificate errors.

**4. Cryptography and Secrets Management**
- Use established cryptographic libraries and standard algorithms.
- Never implement custom cryptographic primitives.
- Use secure random number generators for tokens, keys, and nonces.
- Store passwords using appropriate password hashing algorithms such as Argon2id or bcrypt.
- Never store passwords, API keys, private keys, or tokens in source code.
- Use secret managers or environment-based secret injection where appropriate.
- Define key rotation, revocation, and expiration policies.
- Avoid logging secrets or sensitive cryptographic material.
- Verify encryption mode, nonce requirements, authentication tags, and key handling.

**5. Application and Infrastructure Hardening**
- Apply secure defaults and disable unnecessary services.
- Run workloads with minimum required permissions.
- Avoid privileged containers and unnecessary host mounts.
- Validate container image provenance and dependencies.
- Review Kubernetes RBAC, service accounts, security contexts, NetworkPolicies, and admission controls.
- Restrict network exposure and administrative interfaces.
- Apply appropriate security headers, CORS policies, and cookie attributes.
- Ensure production configurations do not expose debug endpoints or development credentials.

**6. Logging, Monitoring, and Detection**
- Record security-relevant events with consistent timestamps and correlation identifiers.
- Preserve original event data when performing enrichment or normalization.
- Avoid logging passwords, tokens, private keys, and unnecessary personal data.
- Handle missing, malformed, duplicated, and out-of-order events.
- Define detection logic with clear conditions, severity, and investigation context.
- Account for false positives and false negatives.
- Ensure detection rules are tested against both malicious and benign scenarios.
- Make alert generation observable and avoid silent failures in monitoring pipelines.

**7. Vulnerability Scanning and Validation**
- Verify scanner versions, rule versions, configuration, and target scope.
- Distinguish scanner findings from manually confirmed vulnerabilities.
- Deduplicate findings without losing relevant evidence.
- Validate affected versions and vulnerable code paths.

- Include reproduction steps and remediation verification.
- Record scan timestamps and target versions to maintain traceability.

**8. Concurrency and Distributed Systems**
- Handle retries, timeouts, and partial failures explicitly.
- Use idempotency where operations may be retried.
- Prevent duplicate event processing and race conditions.
- Define message acknowledgment and dead-letter behavior.
- Protect Kafka consumers, queues, and background workers from unbounded workloads.
- Apply transaction boundaries and consistency guarantees deliberately.
- Avoid exposing partially initialized state.
- Implement graceful shutdown and resource cleanup.

**9. Database and Data Integrity**
- Use parameterized queries and safe ORM operations.
- Validate input before database mutations.
- Apply transactions for related operations.
- Enforce constraints and referential integrity.
- Prevent SQL injection, mass assignment, and unauthorized data access.

- Verify migrations and rollback procedures.

**10. Security Testing and Remediation**
